# Chapter 7: Big O in Everyday Code (일상적인 코드 속 빅 오)

## 핵심 질문

실무 코드베이스에서 마주치는 함수의 빅 오를 어떻게 판별하는가? 중첩 루프인데 O(N)인 코드, 루프가 두 개인데 O(N)인 코드는 어떻게 가려내는가? O(N×M)과 O(2ᴺ)이라는 새 카테고리는 언제 나타나는가?

---

## 1. 왜 판별 훈련인가

**코드 효율성을 알아내는 것이 최적화의 첫 단계다** — 현재 얼마나 빠른지 모르면 수정본이 더 빠른지도 알 수 없다. 또한 빅 오 카테고리를 알면 애초에 최적화가 필요한지 판단할 수 있다: O(N²)이면 일단 멈추고 더 빠른 대안을 고민해 보라는 신호다(물론 O(N²)이 그 문제의 최선일 수도 있다).

이 장은 실제 코드베이스에 있을 법한 9가지 예제로 판별을 훈련한다. 각 예제의 핵심 순서는 같다: **① N이 무엇인지 확정 → ② N에 비례한 단계 수 계산 → ③ 상수·낮은 차수 제거.**

## 2. 예제 판별 연습

### 2.1 짝수의 평균 — O(N)

배열을 순회하며 짝수만 합과 개수에 반영해 평균을 반환하는 함수. N = 배열 크기. 루프는 N번 돌고, 최악(전부 짝수)에는 루프마다 3단계씩 3N단계 + 루프 밖 초기화·나누기 3단계 = 3N+3. **상수를 모두 버려 O(N).**

### 2.2 단어 생성기 — O(N²), O(N³)

문자 배열로 두 글자짜리 모든 조합(`"ab", "ac", …`)을 만드는 이중 루프: N × N = **O(N²)**. 세 글자 조합이면 삼중 루프로 N × N × N = **O(N³)**. 중첩이 4, 5개면 O(N⁴), O(N⁵)다. O(N³)을 O(N²)으로 낮추는 최적화는 기하급수적 개선이다.

### 2.3 배열 샘플 — O(1)

배열의 맨 앞·가운데·맨 뒤 값을 반환하는 함수. 배열이 아무리 커도 인덱스 계산과 읽기 몇 번뿐 — **O(1)**.

### 2.4 평균 섭씨 온도 — O(N)

화씨 배열을 섭씨로 변환하는 루프 + 합을 구하는 루프. **루프 두 개가 중첩이 아니라 나란히** 실행되므로 N + N = 2N → **O(N)**.

> **핵심 통찰**: 루프 개수가 아니라 **곱해지는가 더해지는가**가 관건이다. 중첩 루프는 N×N(=O(N²)), 순차 루프는 N+N(=O(N)).

### 2.5 의류 상표 — O(N)

품목마다 사이즈 1~5의 상표 문자열을 만드는 중첩 루프. 중첩이지만 **안쪽 루프가 N과 무관하게 항상 5번** 돈다 → 5N → **O(N)**. 중첩 루프가 O(N²)이 되는 건 **양쪽 다 N개씩** 처리할 때만이다.

### 2.6 1 세기 — O(N)

배열들의 배열에서 1의 개수를 세는 이중 루프. 겉보기엔 중첩이지만 **두 루프가 서로 다른 것을 순회**한다 — 바깥은 안쪽 배열들, 안쪽은 실제 수들. 결국 안쪽 루프의 총 실행 횟수 = 전체 수의 개수. N을 "수의 총 개수"로 놓으면 **O(N)**.

### 2.7 팰린드롬 검사기 — O(N)

**팰린드롬(*palindrome - 앞으로 읽으나 뒤로 읽으나 같은 단어/구절. "racecar", "kayak" 등*)** 판별: 양끝에서 시작하는 두 인덱스를 가운데로 모으며 비교.

```typescript
function isPalindrome(string: string): boolean {
  let leftIndex = 0;
  let rightIndex = string.length - 1;
  while (leftIndex < string.length / 2) {
    if (string[leftIndex] !== string[rightIndex]) {
      return false;
    }
    leftIndex++;
    rightIndex--;
  }
  return true;
}
```

루프는 문자열 중간까지만 = N/2단계 → 상수 제거 → **O(N)**.

### 2.8 모든 곱 구하기 — O(N²), 그리고 O(N×M)

배열 내 모든 두 숫자 조합의 곱: 안쪽 루프가 항상 `i+1`에서 시작하므로 실행 횟수는 (N−1) + (N−2) + … + 1 ≈ **N²/2** → **O(N²)**. (N×N 격자를 그려 보면 대각선 위 절반만 칠해지는 그림이 N²/2의 직관적 증명이다.)

**여러 데이터 세트**: 배열 두 개 사이의 모든 곱이라면? N을 "두 배열 합계"로 둘 수 없다 — 크기 5+5(25단계)와 9+1(9단계)은 합이 같은 10이어도 효율이 전혀 다르기 때문이다. 이때는 각 배열을 별개로 두고 **O(N×M)**으로 표현한다.

> **핵심 통찰**: O(N×M)은 N=M이면 O(N²), 한쪽이 1이면 O(N)이 되는, **O(N)과 O(N²) 사이의 범위**로 이해하면 된다. 훌륭한 표현은 아니지만 별개의 두 데이터 세트를 곱하는 알고리즘에서는 이것이 최선이다.

### 2.9 암호 크래커 — O(2ᴺ)의 세계

길이 N의 모든 문자열 조합을 생성하는 **브루트 포스(*brute force - 가능한 모든 경우를 무차별 대입하는 방식*)** 코드. 길이 1이면 26개, 2면 26², 3이면 26³… → **O(26ᴺ)**.

> **핵심 통찰**: O(2ᴺ) 계열은 **O(log N)의 정반대**다. O(log N)은 데이터가 두 배로 늘 때 한 단계 늘지만, O(2ᴺ)은 **데이터가 하나 늘 때 단계가 두 배**가 된다. 그래프에서 O(2ᴺ)은 어느 시점부터 O(N³)조차 추월해 치솟는다 — 브루트 포스 암호 해독이 비효율적인 이유다.

## 3. 카테고리 지도 (지금까지)

| 빅 오 | 이름 | 대표 예 |
|-------|------|---------|
| O(1) | 상수 시간 | 배열 읽기, 배열 샘플 |
| O(log N) | 로그 시간 | 이진 검색 |
| O(N) | 선형 시간 | 선형 검색, 순차 루프들 |
| O(N²) | 이차 시간 | 중첩 루프(양쪽 N), 단순 정렬 |
| O(N³) | 삼차 시간 | 3중 루프 |
| O(2ᴺ)류 | 지수 시간 | 브루트 포스 조합 생성 |

## 요약

- 판별 3단계: **N 확정 → 단계 수 계산 → 상수·낮은 차수 제거**
- 겉모습에 속지 말 것: 중첩 루프라도 안쪽이 상수(의류 상표)거나 다른 데이터를 순회(1 세기)하면 **O(N)**, 루프 두 개라도 순차면 **O(N)**
- "오른쪽만 곱하기" 패턴(모든 곱)은 N²/2 → **O(N²)**
- 별개 데이터 세트 두 개를 곱하면 **O(N×M)** — O(N)과 O(N²) 사이의 범위
- **O(2ᴺ)류(지수 시간)**는 데이터 1개 추가마다 단계가 배수로 증가 — O(log N)의 정반대이자 최악의 카테고리
- 이 판별 능력이 최적화의 출발점이다 — 다음 장부터 속도를 올리는 도구(해시 테이블)가 나온다

## 연습 문제 (해답 예시)

1. **"합이 100인 배열"인지 확인(양끝에서 좁혀오는 while)** — **O(N).** 루프가 N/2번 돌지만 상수를 버린다.
2. **두 정렬된 배열 병합** — **O(N).** 각 값을 정확히 한 번씩 처리하므로 두 배열의 총 원소 수를 N으로 두면 O(N)이다 (O(N+M)으로 쓸 수도 있지만 어차피 더하는 관계이므로 합쳐서 N이 더 간단하다).
3. **모래사장(haystack)에서 바늘(needle) 찾기** — **O(N×M).** 최악에 바늘 문자 수 × 모래사장 문자 수만큼 실행되고 둘의 크기가 다를 수 있다.
4. **세 수의 최대곱(3중 루프)** — **O(N³).** 실제로는 N × N/2 × N/4 ≈ N³/8단계지만 상수를 버린다.
5. **이력서 더미에서 위/아래 절반씩 번갈아 버리기** — **O(log N).** 루프마다 이력서가 절반으로 줄어든다.
