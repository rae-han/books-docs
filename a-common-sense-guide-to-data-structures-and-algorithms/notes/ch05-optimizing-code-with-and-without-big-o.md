# Chapter 5: Optimizing Code with and Without Big O (빅 오를 사용하거나 사용하지 않는 코드 최적화)

## 핵심 질문

빅 오 표기법이 두 알고리즘을 "정확히 같다"고 말하는데 실제로는 한쪽이 두 배 빠르다면, 무슨 일이 벌어진 것인가? 빅 오는 왜 상수를 무시하며, 그럼에도 왜 쓸모 있는 도구인가?

---

## 1. 선택 정렬

버블 정렬(Ch4)과 비교할 두 번째 단순 정렬, **선택 정렬(*selection sort - 패스스루마다 최솟값을 찾아 패스스루 시작 위치와 교환하는 정렬*)**의 단계는 다음과 같다.

1. 왼쪽부터 각 셀을 확인하며 **최솟값의 인덱스**를 변수에 기록한다 (더 작은 값을 만나면 변수를 갱신)
2. 패스스루가 끝나면 최솟값을 **패스스루를 시작한 위치의 값과 교환**한다 (1차 패스스루는 인덱스 0, 2차는 인덱스 1…)
3. 배열 끝에서 시작하는 패스스루에 도달할 때까지 반복한다

`[4, 2, 7, 1, 3]`으로 실행하면: 1차 패스스루에서 비교 4번으로 최솟값 1을 찾아 4와 교환 → `[1, 2, 7, 4, 3]`. 2차에서 비교 3번, 최솟값 2가 이미 제자리라 교환 없음. 3차에서 비교 2번 후 3↔7 교환 → `[1, 2, 3, 4, 7]`. 4차에서 비교 1번, 교환 없음 — 완료.

```typescript
function selectionSort(array: number[]): number[] {
  for (let i = 0; i < array.length - 1; i++) {
    let lowestNumberIndex = i;   // 현재까지의 최솟값 인덱스
    for (let j = i + 1; j < array.length; j++) {
      if (array[j] < array[lowestNumberIndex]) {
        lowestNumberIndex = j;
      }
    }
    // 최솟값이 제자리가 아니면 패스스루 시작 위치와 교환
    if (lowestNumberIndex !== i) {
      [array[i], array[lowestNumberIndex]] = [array[lowestNumberIndex], array[i]];
    }
  }
  return array;
}
```

## 2. 선택 정렬의 효율성 — 버블 정렬의 절반

선택 정렬의 단계도 비교와 교환 두 종류다. 비교 횟수는 버블 정렬과 같은 (N−1) + (N−2) + … + 1이지만, **교환은 패스스루당 최대 한 번**이다(버블 정렬은 최악의 경우 비교마다 교환).

| 원소 개수 (N) | 버블 정렬 최대 단계 | 선택 정렬 최대 단계 |
|--------------|--------------------|--------------------|
| 5 | 20 | 14 (비교 10 + 교환 4) |
| 10 | 90 | 54 (비교 45 + 교환 9) |
| 20 | 380 | 199 (비교 180 + 교환 19) |
| 40 | 1,560 | 819 (비교 780 + 교환 39) |
| 80 | 6,320 | 3,239 (비교 3,160 + 교환 79) |

선택 정렬은 버블 정렬보다 단계가 약 절반, 즉 **두 배 빠르다**. 단계 수로는 대략 N²/2다.

## 3. 상수 무시하기

그런데 빅 오 표기법은 선택 정렬을 O(N²/2)가 아니라 버블 정렬과 똑같은 **O(N²)**으로 표현한다. 빅 오의 첫 번째 공식 규칙 때문이다.

> **핵심 통찰**: **빅 오 표기법은 상수를 무시한다.** 지수가 아닌 수는 표현식에서 그냥 버린다 — N/2단계 → O(N), N²+10단계 → O(N²), 2N단계 → O(N), 심지어 100N단계도 O(N)이다.

O(100N)이 O(N)보다 100배 느린데도 같은 표기라니, 이 규칙은 빅 오를 쓸모없어 보이게 만든다. 어떻게 된 일일까?

## 4. 빅 오 카테고리 — 집과 고층 건물

건물에 비유해 보자. 단독 주택과 고층 건물을 비교할 때 굳이 "2층짜리 집과 100층짜리 건물"이라고 층수를 셀 필요가 없다 — 하나는 집, 하나는 고층 건물이라는 **일반적인 카테고리**만으로 현저한 차이가 드러난다.

> **핵심 통찰**: **빅 오 표기법은 알고리즘 속도의 "일반적인 카테고리"만 다룬다.** O(N)과 O(N²)의 차이는 너무 커서 그 O(N)이 실제로 2N이든 N/2이든 100N이든 중요하지 않다 — O(N)에 어떤 상수를 곱해도 데이터가 커지다 보면 **언젠가 반드시** O(N²)이 더 느려지기 때문이다. O(N)은 직선 성장, O(N²)은 지수 성장이라는 서로 다른 궤적의 문제다.

그래서 도구를 이렇게 나눠 쓴다:

- **다른 카테고리끼리 비교** (O(N) vs O(N²)): 빅 오만으로 충분하다
- **같은 카테고리 안에서 비교** (버블 정렬 vs 선택 정렬, 둘 다 O(N²)): 빅 오는 침묵한다 — **더 세밀한 단계 수 분석**이 필요하다

이 장의 제목이 "빅 오를 사용하거나 사용하지 않는 최적화"인 이유다.

### 4.1 실제 예제 — 짝수 출력 두 버전

Ch1의 짝수 출력 두 함수(상한을 매개변수 `upperLimit`으로)를 빅 오로 보면, 여기서 N은 배열 크기가 아니라 **전달되는 수**다. 버전 1은 N단계 → O(N). 버전 2는 N/2단계 → 상수를 버리면 역시 **O(N)**. 그러나 버전 2가 실제로는 두 배 빠르고 당연히 더 나은 선택이다 — 같은 빅 오라도 분석은 계속해야 한다는 또 하나의 예다.

### 4.2 어떤 단계를 세야 하나

버전 1을 더 파고들면 루프마다 비교(`number % 2 === 0`), 증가(`number += 1`), 그리고 두 번에 한 번 출력이 일어난다. 전부 세면 N + N + N/2 = 2.5N단계다. 어떤 단계가 중요할까?

**모든 단계가 중요하다.** 다만 빅 오로 표현할 때 상수를 버리며 표현식을 단순화할 뿐이다(2.5N → O(N)). 상수를 제거하면 루프 안의 세부 동작보다 **루프가 실질적으로 몇 번 실행되는가**에 초점이 맞춰진다.

## 요약

- **선택 정렬**: 패스스루마다 최솟값을 찾아 시작 위치와 교환 — 교환이 패스스루당 최대 1번이라 버블 정렬보다 **약 2배 빠르다** (≈N²/2단계)
- 그럼에도 빅 오로는 둘 다 **O(N²)** — **빅 오는 상수를 무시한다** (N/2, 2N, 100N → 전부 O(N))
- 이유: 빅 오는 **일반 카테고리**(성장 궤적)만 구분한다. 카테고리가 다르면 상수가 무엇이든 데이터가 커질수록 반드시 역전된다
- 도구 사용법: **카테고리가 다르면 빅 오로 판정, 같으면 추가 분석으로 판정**
- 단계를 셀 때는 모든 단계가 중요하지만, 상수 제거 덕분에 실질적으로는 "루프 실행 횟수"에 집중하게 된다
- 다음 정제: 최악의 시나리오만 보는 것도 전부가 아니다 — 평균 시나리오(Ch6)

## 연습 문제 (해답 예시)

1. **4N + 16단계 알고리즘의 빅 오는?** — **O(N).** 상수 4와 16을 버린다.
2. **2N²단계 알고리즘은?** — **O(N²).** 상수 2를 버린다.
3. **배열의 모든 수를 두 배로 만든 뒤 합을 반환하는 함수(루프 2개 순차 실행)는?** — **O(N).** 2N단계이지만 상수를 버린다.
4. **문자열마다 대문자·소문자·첫 글자 대문자를 출력하는 함수는?** — **O(N).** 루프 안에서 3단계씩, 총 3N단계 → 상수 제거.
5. **짝수 인덱스마다 배열 전체를 다시 순회하며 합을 출력하는 함수는?** — **O(N²).** 안쪽 루프를 절반의 인덱스에서만 실행하므로 N²/2단계이지만, 2로 나누는 상수를 버려 O(N²)이다.

## 다른 챕터와의 관계

- **Ch4 (빅 오로 코드 속도 올리기)**: 버블 정렬 O(N²)의 "같은 카테고리 경쟁자"로 선택 정렬이 등장했다

- **Ch7 (일상적인 코드 속 빅 오)**: 이 장의 "모든 단계 세고 상수 버리기" 기술이 실무 코드 판별 훈련으로 이어진다
- **Ch19 (공간 제약)**: 상수 무시 규칙은 공간 복잡도 분석에도 똑같이 적용된다
