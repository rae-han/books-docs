# Chapter 3: O Yes! Big O Notation (빅 오 표기법)

## 핵심 질문

"22단계짜리 알고리즘"이라고 말할 수 없는 이유는 무엇인가? 알고리즘의 효율을 소통하는 공통 언어는 어떻게 생겼는가? 그리고 항상 3단계 걸리는 알고리즘이 O(3)이 아니라 O(1)인 이유는 무엇인가?

---

## 1. 왜 공통 언어가 필요한가

알고리즘에 필요한 단계 수는 하나의 수로 못 박을 수 없다. 선형 검색은 원소 22개짜리 배열에서는 22단계, 400개짜리에서는 400단계다. "배열에 N개의 원소가 있을 때 N단계가 필요하다"라고 말할 수는 있지만 장황하다.

컴퓨터 과학자들은 시간 복잡도를 간결하고 일관된 언어로 소통하기 위해 수학에서 **빅 오 표기법(*Big O Notation - 알고리즘 효율성을 분류하는 형식화된 표현*)**을 차용했다. 이 책은 수학 용어 없이 컴퓨터 과학과 연관 지어 설명한다.

## 2. 빅 오의 핵심 질문

> **핵심 통찰**: 빅 오 표기법은 단 하나의 **핵심 질문**에 대한 답이다 - **"데이터 원소가 N개일 때, 알고리즘에 몇 단계가 필요할까?"** 답은 괄호 안에 들어간다. 이 책 전반에서 사용할 빅 오의 정의이므로 머릿속에 선명히 새겨두자.

- **선형 검색**: 최악의 경우 원소 수만큼 단계가 필요 → **O(N)** ("오 N"). O(N) 알고리즘은 **선형 시간(linear time)** 알고리즘이라고도 부른다.
- **배열 읽기**: 배열 크기와 무관하게 1단계 → **O(1)** ("오 1"). 데이터가 늘어도 단계 수가 늘지 않으므로 "가장 빠른" 알고리즘 유형이며 **상수 시간(constant time)** 알고리즘이라 부른다. N에 대해 물었는데 답이 N과 무관하다는 점이 핵심이다.

수학적 배경이 궁금하다면 "Introduction to Algorithms"(코멘 외)의 형식적 정의(함수 증가율의 상한)를 참고할 수 있지만, 이 책의 설명만으로 실용적 이해에는 충분하다.

## 3. 빅 오의 본질 - 데이터가 늘 때 성능이 어떻게 변하는가

데이터가 몇 개든 항상 3단계 걸리는 알고리즘은 O(3)일까? 아니다 - **O(1)이다.**

> **핵심 통찰**: 빅 오의 본질은 단계 수 자체가 아니라 **"데이터가 늘어날 때 알고리즘의 단계 수가 어떻게 증가하는가"**다. 이 관점에서 3단계든 1단계든 100단계든, 데이터 증가에 영향을 받지 않는 알고리즘은 전부 같은 유형(상수 시간)이므로 구분할 이유가 없다.

그래프로 보면 O(N)은 완벽한 대각선(데이터 하나 추가 = 한 단계 추가), O(1)은 완벽한 수평선이다.

### 3.1 항상 100단계 걸리는 O(1) vs O(N)

항상 100단계가 걸리는 상수 시간 알고리즘도 O(N)보다 효율적이라고 말할 수 있을까? 원소 100개 이하에서는 O(N)이 오히려 단계가 적다. 하지만 원소가 100개를 넘는 순간부터 **무한대까지** O(N)이 더 많은 단계를 쓴다. 이렇게 역전이 일어나는 데이터 크기가 반드시 존재하고 그 뒤로는 영원히 바뀌지 않으므로, O(1) 알고리즘이 실제로 몇 단계이든 전반적으로 O(N)보다 효율적이라 말한다(백만 단계짜리 O(1)이라도 마찬가지다).

### 3.2 같은 알고리즘, 다른 시나리오

선형 검색이 항상 O(N)인 것도 아니다. 찾는 값이 첫 셀에 있으면 1단계, 즉 O(1)이다. 정리하면 선형 검색은 **최선의 시나리오에서 O(1), 최악의 시나리오에서 O(N)**이다.

별도로 명시하지 않는 한 **빅 오 표기법은 일반적으로 최악의 시나리오를 의미**한다. 이런 "비관적" 접근은 최악에 대비하게 해주고 알고리즘 선택에 중요한 판단 근거가 되기 때문에 유용하다.

## 4. 세 번째 유형 - O(log N)

이진 검색은 어디에 속할까? 데이터가 커지면 단계도 늘어나므로 O(1)은 아니고, 원소 100개에 7단계뿐이니 O(N)도 아니다. 둘 사이 어딘가 - 빅 오는 이를 **O(log N)**("오 로그 N")이라 표현하며, **로그 시간(log time)** 알고리즘이라 부른다.

**간단히 말해 O(log N)은 데이터가 두 배로 증가할 때마다 단계가 하나씩 늘어나는 알고리즘이다.** 지금까지 배운 세 유형을 효율 순으로 나열하면:

O(1) < O(log N) < O(N) (왼쪽이 빠름)

### 4.1 로가리즘(logarithm)

로가리즘은 알고리즘과 발음만 비슷할 뿐 아무 관련이 없는 수학 개념으로, **지수의 역**이다.

- 교과서 정의: 2³ = 8이므로 log₂8 = 3 ("2를 몇 번 곱해야 8이 되는가")
- 이 책의 직관적 정의: **"1이 될 때까지 8을 2로 몇 번 나눠야 하는가"** - 8/2/2/2 = 1이므로 3. 마찬가지로 64는 6번 나눠야 1이 되므로 log₂64 = 6

### 4.2 O(log N) 해석

컴퓨터 과학의 O(log N)은 사실 O(log₂N)의 줄임말이다(밑 2 생략). 핵심 질문에 대입하면: **원소가 N개일 때 log₂N단계가 걸린다** - 즉 **원소가 하나 남을 때까지 데이터를 계속 반으로 줄이는 만큼의 단계 수**다. 이진 검색이 정확히 이렇게 동작한다.

| 원소 개수 (N) | O(N) | O(log N) |
|--------------|------|----------|
| 8 | 8 | 3 |
| 16 | 16 | 4 |
| 32 | 32 | 5 |
| 64 | 64 | 6 |
| 128 | 128 | 7 |
| 256 | 256 | 8 |
| 512 | 512 | 9 |
| 1024 | 1024 | 10 |

## 5. 실제 코드에서 빅 오 읽기

**리스트 출력** - 뭔가를 하는 코드는 모두 엄밀히 알고리즘이다. 원소 수만큼 루프가 돌므로 O(N):

```typescript
const things = ["apples", "baboons", "cribs", "dulcimers"];
for (const thing of things) {
  console.log(`Here's a thing: ${thing}`);  // N번 실행 → O(N)
}
```

**소수 판별** - 여기서는 N이 배열 크기가 아니라 **함수에 전달되는 수**다:

```typescript
function isPrime(number: number): boolean {
  for (let i = 2; i < number; i++) {
    if (number % i === 0) {
      return false;
    }
  }
  return true;
}
```

핵심 질문을 상황에 맞게 바꿔야 한다: "number에 N을 전달할 때 몇 단계가 필요할까?" 루프가 전달된 수에 비례해 돌므로 O(N)이다.

> **핵심 통찰**: **N이 무엇인지 찾는 것**이 빅 오 분석의 첫 단추다. N은 배열의 원소 수일 수도, 함수에 전달된 수 자체일 수도 있다 - 알고리즘의 단계 수를 좌우하는 "주요 데이터"가 N이다.

## 요약

- 빅 오 표기법 = 핵심 질문 **"데이터 원소가 N개일 때 몇 단계가 필요한가?"**에 대한 답
- **빅 오의 본질**: 단계 수 자체가 아니라 **데이터 증가에 따른 단계 수의 증가 방식** - 그래서 3단계든 100단계든 상수면 전부 O(1)
- 빅 오는 별도 언급이 없으면 **최악의 시나리오** 기준
- 세 가지 기본 유형: **O(1)** 상수 시간(수평선) / **O(log N)** 로그 시간(데이터 2배당 +1단계) / **O(N)** 선형 시간(대각선)
- log₂N = "1이 될 때까지 N을 2로 나누는 횟수" - 이진 검색이 O(log N)인 이유
- 실전 분석의 첫 단추는 **N이 무엇인지**(배열 크기? 전달된 수?) 찾는 것

## 연습 문제 (해답 예시)

1. **윤년 판별 함수(`year % 100 === 0 ? … : …`)의 빅 오는?** - **O(1).** 전달된 년도가 무엇이든 단계 수가 일정하다.
2. **배열 원소를 전부 합하는 함수의 빅 오는?** - **O(N).** 원소 N개면 루프가 N번 돈다.
3. **체스판 쌀알 함수(쌀이 목표량에 이를 때까지 `placedGrains *= 2`)의 빅 오는?** - **O(log N).** N(목표 쌀알 수)이 두 배가 될 때마다 루프가 한 번 더 돈다 (256 → 9회, 512 → 10회, 1024 → 11회).
4. **"a"로 시작하는 문자열만 골라 새 배열을 만드는 함수의 빅 오는?** - **O(N).** 문자열 N개를 전부 순회한다.
5. **정렬된 배열의 중앙값을 구하는 함수의 빅 오는?** - **O(1).** 배열 크기가 얼마든 가운데 인덱스 계산과 읽기만 하므로 정해진 단계만 걸린다.
