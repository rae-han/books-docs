# Chapter 4: Speeding Up Your Code with Big O (빅 오로 코드 속도 올리기)

## 핵심 질문

빅 오가 내 알고리즘에 "느리다"는 꼬리표를 붙였을 때 무엇을 해야 하는가? 중첩 루프를 보면 왜 머릿속에 경보가 울려야 하는가? O(N²) 코드는 어떻게 O(N)으로 최적화되는가?

---

## 1. 빅 오는 최적화의 나침반이다

빅 오를 알면 내 알고리즘을 세상의 범용 알고리즘과 비교하며 "일반적으로 쓰이는 알고리즘만큼 빠른가?"를 자문할 수 있다.

> **핵심 통찰**: 빅 오에서 내 알고리즘이 "느린" 카테고리에 속한다면, 한 발짝 물러나 **더 빠른 빅 오 카테고리로 들어갈 수 있는지** 고민해 보라. 항상 가능하지는 않지만, 불가능하다고 결론 내리기 전에 꼭 생각해 볼 가치가 있다.

이 장은 새 카테고리 O(N²)을 소개하고, 실제 문제에서 O(N²) 코드를 O(N)으로 최적화하는 과정을 보여준다.

## 2. 버블 정렬

**정렬 알고리즘**(정렬되지 않은 배열을 오름차순으로 만드는 알고리즘)은 컴퓨터 과학에서 폭넓게 연구된 주제다. 그중 이해하기 쉽지만 비효율적인 부류를 **단순 정렬(simple sort)**이라 부른다. 첫 번째 주자가 **버블 정렬(*bubble sort - 인접한 두 값을 비교·교환하며 가장 큰 값을 끝으로 밀어 올리는 정렬*)**이다.

1. 연속된 두 항목을 가리켜 **비교**한다 (처음에는 첫 두 항목)
2. 순서가 뒤바뀌어 있으면(왼쪽이 크면) **교환(swap)**한다
3. 포인터를 오른쪽으로 한 칸 옮긴다
4. 배열 끝(또는 이미 정렬된 값)까지 1~3을 반복 - 이것이 한 번의 **패스스루(*pass-through - 배열을 처음부터 끝까지 한 번 통과하는 것*)**
5. 교환이 한 번도 일어나지 않는 패스스루가 나올 때까지 패스스루를 반복한다

`[4, 2, 7, 1, 3]`으로 실행하면: 1차 패스스루(7단계)에서 7이 맨 끝으로, 2차(5단계)에서 4가 제자리로, 3차(3단계)에서 3이, 4차(1단계)는 교환 없음 → 정렬 완료. **각 패스스루마다 정렬되지 않은 값 중 가장 큰 값("버블")이 올바른 위치로 떠오르기** 때문에 버블 정렬이라 부른다.

```typescript
function bubbleSort(list: number[]): number[] {
  // 아직 정렬되지 않은 구간의 가장 오른쪽 인덱스
  let unsortedUntilIndex = list.length - 1;
  let sorted = false;

  while (!sorted) {
    sorted = true;  // 교환이 없으면 그대로 true로 남아 종료된다
    for (let i = 0; i < unsortedUntilIndex; i++) {
      if (list[i] > list[i + 1]) {
        [list[i], list[i + 1]] = [list[i + 1], list[i]];  // 교환
        sorted = false;
      }
    }
    // 이번 패스스루로 버블 하나가 제자리를 찾았다
    unsortedUntilIndex -= 1;
  }
  return list;
}
```

## 3. 버블 정렬의 효율성 - O(N²)

버블 정렬에는 두 종류의 단계가 있다: **비교**와 **교환**.

- **비교 횟수**: 원소 5개면 패스스루마다 4, 3, 2, 1번 = 10번. 일반화하면 (N-1) + (N-2) + … + 1
- **교환 횟수**: 최악(완전 역순 배열)에는 비교할 때마다 교환하므로 비교 횟수와 같다

| 원소 개수 (N) | 버블 정렬 최대 단계 수 | N² |
|--------------|----------------------|-----|
| 5 | 20 | 25 |
| 10 | 90 | 100 |
| 20 | 380 | 400 |
| 40 | 1,560 | 1,600 |
| 80 | 6,320 | 6,400 |

단계 수가 대략 N²으로 늘어난다 → 버블 정렬은 **O(N²)**이며, **이차 시간(quadratic time)**이라고도 부른다. 그래프에서 O(N²)은 O(N)의 대각선보다 훨씬 가파르게 치솟는다.

## 4. 이차 문제 - 중복 값 검사

사용자 평점(1~10) 배열에 중복 숫자가 있는지 확인하는 함수를 짠다고 하자. 가장 먼저 떠오르는 방법은 중첩 루프다:

```typescript
function hasDuplicateValue(array: number[]): boolean {
  for (let i = 0; i < array.length; i++) {
    for (let j = 0; j < array.length; j++) {
      if (i !== j && array[i] === array[j]) {
        return true;
      }
    }
  }
  return false;
}
```

빅 오 분석: 단계 유형은 비교 하나이고, 최악의 시나리오는 **중복이 없어서** 모든 조합을 다 비교하고 false를 반환하는 경우다. 바깥 루프 N번 × 안쪽 루프 N번 = **N²번 비교 → O(N²)**. (단계 카운터를 심어 실행해 보면 원소 5개에 정확히 25가 출력된다.)

> **핵심 통찰**: **루프 안에 루프를 중첩하는 알고리즘은 대부분(항상은 아니다) O(N²)이다. 중첩 루프가 보이면 머릿속에 O(N²) 경보가 울려야 한다.** O(N²)은 상대적으로 느린 알고리즘이므로, 마주치면 시간을 들여 더 빠른 대안을 깊이 고민해 볼 신호다. 더 나은 방법이 없을 수도 있지만, 먼저 확인부터 하자.

## 5. 선형 해결법 - O(N)

중첩 루프 없이 같은 문제를 푸는 영리한 방법:

```typescript
function hasDuplicateValue(array: number[]): boolean {
  const existingNumbers: number[] = [];
  for (let i = 0; i < array.length; i++) {
    if (existingNumbers[array[i]] === 1) {
      return true;             // 이미 나온 숫자 → 중복 발견
    } else {
      existingNumbers[array[i]] = 1;  // "이 숫자 나왔음"을 인덱스에 기록
    }
  }
  return false;
}
```

`existingNumbers`의 **인덱스 자체를 "지금까지 나온 숫자"의 기억 장치로** 쓴다. `[3, 5, 8]`을 처리하면 인덱스 3, 5, 8에 1이 채워진다: `[undefined, undefined, undefined, 1, undefined, 1, undefined, undefined, 1]`. 1을 저장하기 전에 그 인덱스가 이미 1인지 확인하고, 1이면 중복이므로 즉시 true.

최악의 시나리오(중복 없음)에도 루프는 한 번, N단계 → **O(N)**. O(N²)에서 O(N)으로, 엄청난 속도 향상이다.

(단점: 첫 번째 방식보다 **메모리를 더 소비**한다. `existingNumbers`라는 추가 배열이 필요하기 때문인데, 시간-공간 트레이드오프는 Ch19에서 상세히 다룬다.)

## 요약

- 빅 오는 비교 도구를 넘어 **최적화의 출발점**이다: 느린 카테고리 판정 = 더 빠른 카테고리를 찾아보라는 신호
- **버블 정렬**: 인접 비교·교환의 패스스루 반복, 패스스루마다 최댓값이 끝으로 "떠오름" - 비교 (N-1)+…+1회 + 교환으로 **O(N²)** (이차 시간)
- **중첩 루프 = O(N²) 경보.** 대부분의 중첩 루프 알고리즘이 이차 시간이다
- 중복 검사 예제: 중첩 루프 O(N²) → **배열 인덱스를 기억 장치로 쓰는 한 번 순회**로 O(N)
- 빠른 알고리즘이 공짜는 아니다 - O(N) 해법은 추가 메모리를 쓴다(Ch19의 예고)
- 빅 오가 같아서 비교가 안 되는 두 알고리즘의 우열은 다음 장(Ch5)의 주제

## 연습 문제 (해답 예시)

1. **표의 물음표 채우기** - N=100: O(N)=100, O(log N)≈7, O(N²)=10,000 / N=2,000: O(N)=2,000, O(log N)≈11, O(N²)=4,000,000
2. **O(N²) 알고리즘이 256단계 걸렸다면 배열 크기는?** - **16.** 16² = 256 (256의 제곱근).
3. **모든 숫자 쌍의 최대곱을 찾는 이중 루프 함수의 빅 오는?** - **O(N²).** 바깥 루프 N번 × 안쪽 루프 N번.
4. **O(N²)인 최댓값 찾기 함수를 O(N)으로 다시 작성하면?**

   ```typescript
   function greatestNumber(array: number[]): number {
     let greatestNumberSoFar = array[0];
     for (const i of array) {
       if (i > greatestNumberSoFar) {
         greatestNumberSoFar = i;
       }
     }
     return greatestNumberSoFar;
   }
   ```

   "지금까지의 최댓값" 하나만 유지하며 한 번만 순회한다.

## 다른 챕터와의 관계

- **Ch3 (빅 오 표기법)**: O(1)/O(log N)/O(N)에 네 번째 유형 **O(N²)**이 추가됐다
- **Ch5 (빅 오를 사용하거나 사용하지 않는 코드 최적화)**: 버블 정렬과 같은 O(N²)이지만 실제로는 더 빠른 선택 정렬이 등장 - 빅 오가 못 가리는 우열을 다룬다
- **Ch8 (해시 테이블)**: 이 장의 "인덱스를 기억 장치로" 트릭의 일반화가 해시 테이블 룩업이다
- **Ch19 (공간 제약)**: O(N) 해법이 지불한 메모리 비용을 정식으로 분석한다
