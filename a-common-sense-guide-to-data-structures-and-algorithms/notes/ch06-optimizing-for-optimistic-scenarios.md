# Chapter 6: Optimizing for Optimistic Scenarios (긍정적인 시나리오 최적화)

## 핵심 질문

최악의 시나리오만 준비하면 정말 충분한가? 최악에서는 선택 정렬에 지지만 현실에서는 대등한 삽입 정렬의 비밀은 무엇인가? 가장 자주 일어나는 시나리오는 어느 쪽인가?

---

## 1. 왜 최악만 보면 안 되는가

지금까지 최악의 시나리오에 초점을 맞춘 이유는 간단하다 — 최악을 준비하면 모든 일이 순조롭기 때문이다. 하지만 이 장은 최악 외에도 고려할 가치가 있는 시나리오가 있음을 보인다. **모든 시나리오를 고려하는 능력은 상황에 맞는 알고리즘을 고르는 핵심 능력**이다.

## 2. 삽입 정렬

세 번째 단순 정렬인 **삽입 정렬(*insertion sort - 값을 하나 빼내 왼쪽의 큰 값들을 오른쪽으로 시프트한 뒤 제자리에 끼워 넣는 정렬*)**의 수행 순서:

1. 첫 패스스루에서 인덱스 1의 값을 임시로 삭제해 `tempValue` 변수에 저장한다 (그 자리에 공백이 생김). 이후 패스스루마다 다음 인덱스의 값을 삭제한다
2. **시프트 단계**: 공백 왼쪽의 값들을 `tempValue`와 비교해, 더 크면 오른쪽으로 시프트한다 (공백이 왼쪽으로 이동). `tempValue`보다 작은 값을 만나거나 배열 왼쪽 끝에 도달하면 종료
3. `tempValue`를 공백에 삽입한다
4. 마지막 인덱스에서 시작하는 패스스루까지 반복하면 정렬 완료

`[4, 2, 7, 1, 3]` 실행: 1차(2 삽입: 비교 1·시프트 1) → `[2, 4, 7, 1, 3]`, 2차(7은 제자리: 비교 1·시프트 0), 3차(1 삽입: 비교 3·시프트 3) → `[1, 2, 4, 7, 3]`, 4차(3 삽입: 비교 3·시프트 2) → `[1, 2, 3, 4, 7]`.

```typescript
function insertionSort(array: number[]): number[] {
  for (let index = 1; index < array.length; index++) {
    const tempValue = array[index];   // 이번 패스스루에서 "빼낸" 값
    let position = index - 1;         // tempValue와 비교할 왼쪽 위치

    while (position >= 0) {
      if (array[position] > tempValue) {
        array[position + 1] = array[position];  // 오른쪽으로 시프트
        position -= 1;
      } else {
        break;  // 더 작은 값을 만나면 시프트 종료 (조기 탈출!)
      }
    }
    array[position + 1] = tempValue;  // 공백에 삽입
  }
  return array;
}
```

## 3. 삽입 정렬의 효율성 — 그리고 빅 오의 두 번째 규칙

삽입 정렬의 단계는 **삭제·비교·시프트·삽입** 네 종류다. 최악(역순 배열) 기준으로:

- 비교: 1 + 2 + … + (N−1) ≈ N²/2
- 시프트: 비교마다 일어나므로 ≈ N²/2
- 삭제·삽입: 패스스루당 각 1번 = 각 N−1번

합계: N² + 2N − 2단계. 상수를 버리면 O(N² + N). 여기서 빅 오의 두 번째 규칙이 등장한다.

> **핵심 통찰**: **다양한 차수가 섞여 있으면 빅 오는 가장 높은 차수의 N만 남긴다.** N⁴+N³+N²+N단계 → O(N⁴). N이 커질수록 최고 차수의 비중이 압도적이어서 낮은 차수는 미미해지기 때문이다 (N=100일 때 N⁴+N³+N²+N = 101,010,100 ≈ 100,000,000 = N⁴).

따라서 삽입 정렬은 **O(N²)** — 최악 기준으로는 버블 정렬만큼 느리고, 선택 정렬(N²/2)이 셋 중 최고처럼 보인다. 하지만 이야기는 여기서 끝나지 않는다.

## 4. 평균적인 경우

> **핵심 통찰**: **정의상 가장 자주 일어나는 경우가 평균 시나리오다.** 종 곡선을 그려 보면 최선·최악은 드물고 대부분은 평균이 발생한다. 임의의 배열이 완벽한 오름차순/내림차순일 확률이 얼마나 되겠는가 — 값들이 흩어져 있는 경우가 압도적이다.

삽입 정렬의 시나리오별 성능(핵심은 `break`에 의한 **조기 종료**):

- **최악(역순)**: 모든 값을 비교·시프트 → N²단계
- **평균(임의)**: 대체로 절반만 비교·시프트 → N²/2단계
- **최선(정렬됨)**: 패스스루당 비교 1번, 시프트 0번 → 약 N단계

예: `[4, 3, 2, 1]`(최악)은 비교 6+시프트 6=12단계, `[1, 3, 4, 2]`(평균적)는 비교 4+시프트 2=6단계, `[1, 2, 3, 4]`(최선)는 비교 3+시프트 0.

반면 **선택 정렬은 모든 시나리오에서 N²/2단계**다 — 패스스루를 조기에 끝낼 메커니즘이 없어서 항상 남은 값 전부와 비교해야 하기 때문이다.

| 시나리오 | 선택 정렬 | 삽입 정렬 |
|----------|-----------|-----------|
| 최선 | N²/2 | N |
| 평균 | N²/2 | N²/2 |
| 최악 | N²/2 | N² |

**어느 쪽이 나은가? 경우에 따라 다르다.** 평균(임의 데이터)에서는 비등하다. 거의 정렬된 데이터를 다룰 근거가 있다면 삽입 정렬, 대부분 역순일 근거가 있다면 선택 정렬. 데이터를 전혀 모르면 평균 가정으로 둘 다 같다.

## 5. 실제 예제 — 교집합 함수

두 배열의 **교집합**(양쪽 모두에 들어 있는 값 리스트)을 구하는 함수:

```typescript
function intersection(firstArray: number[], secondArray: number[]): number[] {
  const result: number[] = [];
  for (let i = 0; i < firstArray.length; i++) {
    for (let j = 0; j < secondArray.length; j++) {
      if (firstArray[i] === secondArray[j]) {
        result.push(firstArray[i]);
        break;  // ← 이 한 단어가 최적화의 전부
      }
    }
  }
  return result;
}
```

`break` 없는 첫 구현은 비교 N²번(같은 크기 기준)에 삽입 최대 N번 — 낮은 차수 N을 버려 O(N²)이다(크기가 다르면 O(N×M)). 문제는 **일치 값을 찾은 뒤에도 안쪽 루프를 끝까지 돈다**는 것 — 이미 result에 넣었는데 무엇을 더 확인하는가?

`break` 한 단어를 추가하면: 공통 값이 전혀 없는 최악은 여전히 N²번 비교하지만, 두 배열이 동일한 최선은 N번, 일부만 공유하는 평균은 그 사이가 된다. **최악의 빅 오는 그대로여도 평균·최선을 크게 최적화한 것**이며, 이것이 이 장 제목의 의미다.

## 요약

- 최악 대비는 좋지만 **실제로 대부분 일어나는 것은 평균 시나리오**다 — 최선·평균·최악을 구분하는 능력이 알고리즘 선택의 핵심 기술
- **삽입 정렬**: 값을 빼서(tempValue) 왼쪽 큰 값들을 시프트하고 제자리에 삽입 — `break` 조기 종료 덕에 시나리오별 성능이 크게 달라진다 (최선 N / 평균 N²/2 / 최악 N²)
- **빅 오 규칙 2**: 차수가 섞이면 **최고 차수만 남긴다** (N²+N → O(N²))
- 선택 정렬은 조기 종료가 없어 **모든 시나리오에서 N²/2** — 그래서 "삽입 vs 선택"의 답은 데이터 성격에 달렸다
- 교집합 예제: `break` 하나로 최악은 그대로 두고 **평균·최선 시나리오를 최적화**할 수 있다

## 연습 문제 (해답 예시)

1. **3N² + 2N + 1단계의 빅 오는?** — **O(N²).** 상수를 제거하면 N²+N, 낮은 차수 N도 버린다.
2. **N + log N단계는?** — **O(N).** log N은 N보다 낮은 차수이므로 버린다.
3. **합이 10인 쌍을 찾는 이중 루프 함수의 시나리오는?** — 찾는 즉시 반환하므로 **최선 = 첫 두 숫자의 합이 10**, **평균 = 쌍이 배열 중간쯤**, **최악 = 합 10인 쌍이 없어 두 루프를 끝까지 실행.** 최악은 **O(N²)**.
4. **문자열에 "X"가 있는지 확인하는 함수의 빅 오와 개선법은?** — **O(N).** 다만 "X"를 찾아도 루프를 계속 도는 것이 낭비이므로, 찾는 즉시 `return true`하면 최선·평균 시나리오가 개선된다:

   ```typescript
   function containsX(string: string): boolean {
     for (let i = 0; i < string.length; i++) {
       if (string[i] === "X") {
         return true;
       }
     }
     return false;
   }
   ```
