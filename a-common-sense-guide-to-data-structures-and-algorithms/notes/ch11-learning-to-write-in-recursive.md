# Chapter 11: Learning to Write in Recursive (재귀적으로 작성하는 법)

## 핵심 질문

재귀를 이해하는 것과 재귀 함수를 직접 쓰는 것의 간극은 어떻게 메우는가? "이 함수가 이미 구현돼 있다고 상상하라"는 하향식 사고는 어떻게 문제를 놀랍도록 단순하게 만드는가?

---

## 1. 두 가지 재귀 카테고리

재귀 문제에는 "카테고리"가 있고, 카테고리별 기법을 익히면 같은 부류의 문제에 재적용할 수 있다. (이 장은 재귀의 효율성은 다루지 않는다 - 재귀는 시간 복잡도에 몹시 부정적일 수 있지만 그것은 Ch12의 주제다. 우선 재귀적 사고방식에 집중하자.)

### 카테고리 1: 반복 실행

한 작업을 반복적으로 실행하는 알고리즘 - 카운트다운(숫자 출력 반복), 디렉터리 출력(이름 출력 반복). 특징은 **함수의 마지막 줄이 단순히 자신을 다시 호출**한다는 것이다.

**재귀 트릭 - 추가 인자 넘기기.** 배열의 각 수를 제자리에서 두 배로 만드는 함수를 짜 보자. 루프라면 인덱스 변수를 증가시키면 되는데, 재귀에서는 인덱스를 기록할 곳이 없다. 해결책: **인자를 하나 더 전달하자.**

```typescript
function doubleArray(array: number[], index = 0): number[] {
  // 기저 조건: 인덱스가 배열 끝을 지날 때
  if (index >= array.length) {
    return array;
  }
  array[index] *= 2;
  doubleArray(array, index + 1);  // 증가한 인덱스를 함께 전달
  return array;
}
```

인자 기본값(`index = 0`) 덕에 최초 호출은 `doubleArray([1, 2, 3])`처럼 깔끔하게 유지된다. 이 "추가 인자" 비법은 재귀 작성의 일반적이고 편리한 기법이다.

참고 - **제자리(in-place) 수정**: 새 배열을 만들어 반환하는 방식과 달리, 전달받은 원본 배열 자체를 바꾸는 방식이다. 어느 쪽을 쓸지는 프로젝트 상황에 달렸다(Ch19에서 재론).

### 카테고리 2: 계산 (하위 문제 기반)

입력을 받아 계산 결과를 반환하는 함수들. 재귀가 유용한 두 번째 영역은 **하위 문제(*subproblem - 입력을 더 작게 한 똑같은 문제*)의 결과에 기반해 계산할 수 있을 때**다.

계승으로 보면: factorial(6) = 6 × factorial(5). factorial(5)가 큰 문제의 결과 계산에 쓰이는 더 작은 같은 문제, 즉 하위 문제다.

**두 가지 계산 방식**: 1부터 곱해 올라가는 **상향식(bottom up)**과, 하위 문제에 기반하는 **하향식(top down)**. 상향식은 루프로도 재귀로도(추가 인자 비법으로) 구현할 수 있지만 재귀로 할 이점이 없다. 반면 **하향식은 재귀로만 구현할 수 있다** - 이것이 재귀가 강력한 도구인 주된 이유다.

## 2. 하향식 재귀 - 새로운 사고방식

> **핵심 통찰**: 하향식 사고의 본질은 **"문제를 뒤로 미루기"**다. `return number * factorial(number - 1)`을 쓸 때 factorial이 내부적으로 어떻게 동작하는지 알 필요가 없다 - 다른 함수를 호출할 때 늘 그렇듯 올바른 값을 반환하리라 가정하면 된다. 묘하게도 그 함수의 작성자가 자신인데도! **어떻게 푸는지 몰라도 문제를 풀 수 있는** 사고법이다.

하향식 사고 절차 세 단계:

1. **작성 중인 함수가 이미 구현돼 있다고 상상한다**
2. **하위 문제를 찾는다** (보통 "다음으로 가장 작은 문제")
3. **하위 문제에 함수를 호출하면 어떻게 되는지 보고 거기서 시작한다**

### 2.1 배열 합

`sum([1, 2, 3, 4, 5])` = 15를 재귀로. 하위 문제는 첫 원소를 뺀 `[2, 3, 4, 5]`. sum이 잘 동작한다고 믿으면 `sum([2,3,4,5])` = 14이므로, 답은 `array[0] + sum(나머지)`:

```typescript
function sum(array: number[]): number {
  // 기저 조건: 원소가 하나만 남았을 때
  if (array.length === 1) {
    return array[0];
  }
  return array[0] + sum(array.slice(1));
}
```

### 2.2 문자열 뒤집기

`"abcde"`의 하위 문제는 `"bcde"`. `reverse("bcde")` = `"edcb"`라고 믿으면, 끝에 첫 문자만 붙이면 된다:

```typescript
function reverse(string: string): string {
  if (string.length === 1) {
    return string[0];  // 기저 조건
  }
  return reverse(string.slice(1)) + string[0];
}
```

### 2.3 X 세기

`countX("axbxcxd")` = 3. 하위 문제 결과에 첫 문자가 "x"면 1을 더한다. 기저 조건 트릭: 문자 1개 조건으로 하면 분기가 두 개 필요해 지저분해지는데, 많은 언어에서 `string.slice(1)`이 빈 문자열을 반환하므로 **빈 문자열을 기저 조건**으로 하면 깔끔하다:

```typescript
function countX(string: string): number {
  if (string.length === 0) {
    return 0;  // 기저 조건: 빈 문자열엔 x가 없다
  }
  if (string[0] === "x") {
    return 1 + countX(string.slice(1));
  } else {
    return countX(string.slice(1));
  }
}
```

## 3. 계단 문제 - 하향식이 진가를 발휘하는 곳

"간단한 계산은 루프로 충분한데 왜 새 사고법이 필요한가?"라는 의심에 대한 답이 **계단 문제**다:

**N개짜리 계단을 한 번에 1, 2, 3계단씩 오를 수 있을 때, 꼭대기까지 가는 경로는 몇 개인가?**

상향식으로 세어 보면 계단 1개=1, 2개=2, 3개=4, 4개=7… 5개부터는 손으로 세기도 벅차고, 11개면 알고리즘이 떠오르지 않는다. 하향식으로 생각하면:

- 11계단 꼭대기로 가는 마지막 걸음은 반드시 10번째(1계단 점프), 9번째(2계단), 8번째(3계단) 중 한 곳에서 온다 - 그 외에는 불가능
- 세 경우의 경로는 서로 겹치지 않는다
- 따라서 **경로 수 = 10번째까지의 경로 수 + 9번째까지 + 8번째까지**

```typescript
function numberOfPaths(n: number): number {
  if (n < 0) {
    return 0;
  }
  if (n === 1 || n === 0) {
    return 1;
  }
  return numberOfPaths(n - 1) + numberOfPaths(n - 2) + numberOfPaths(n - 3);
}
```

기저 조건은 까다롭다 - n=1·2·3을 전부 하드코딩할 수도 있지만, `n < 0 → 0`, `n === 1 || n === 0 → 1`이라는 두 줄로 "조작"하면 numberOfPaths(2) = 1+1+0 = 2, numberOfPaths(3) = 2+1+1 = 4가 정확히 맞아떨어진다.

## 4. 애너그램 생성 - 종합 문제

**애너그램(*anagram - 문자열 내 모든 문자를 재배열한 문자열*)**을 전부 반환하는 함수. `"abcd"`의 하위 문제는 `"bcd"` - `anagramsOf("bcd")`가 6개의 애너그램을 준다고 믿으면, **각 애너그램의 가능한 모든 자리(4곳)에 "a"를 끼워 넣어** "abcd"의 24개 순열을 만들 수 있다:

```typescript
function anagramsOf(string: string): string[] {
  // 기저 조건: 문자 하나면 그 문자 하나짜리 배열
  if (string.length === 1) {
    return [string[0]];
  }

  const collection: string[] = [];
  // 하위 문제: 첫 문자를 뺀 부분 문자열의 모든 애너그램
  const substringAnagrams = anagramsOf(string.slice(1));

  for (const substringAnagram of substringAnagrams) {
    // 부분 애너그램의 각 자리(끝 포함)에 첫 문자를 삽입
    for (let index = 0; index <= substringAnagram.length; index++) {
      const copy =
        substringAnagram.slice(0, index) + string[0] + substringAnagram.slice(index);
      collection.push(copy);
    }
  }
  return collection;
}
```

주목: **루프와 재귀를 함께 쓴다.** 재귀를 쓴다고 루프를 전부 없애야 하는 것이 아니다 - 문제를 가장 자연스럽게 푸는 도구를 조합한다.

**효율성**: 문자 N개의 애너그램은 N × (N-1) × … × 1 = **N!개**다. 새로운 빅 오 카테고리 **O(N!)** - **계승 시간(factorial time)**으로, O(2ᴺ)보다도 느리다. 하지만 애너그램을 "전부" 생성해야 하고 그 수 자체가 N!이니 더 나은 방법이 없다.

## 요약

- 재귀 카테고리 ①: **반복 실행** - 마지막 줄에서 자신을 호출. 인덱스 등 상태는 **추가 인자**(+기본값)로 넘긴다
- 재귀 카테고리 ②: **계산** - **하위 문제**(입력이 더 작은 같은 문제)의 결과에 기반
- 상향식은 루프/재귀 모두 가능하지만, **하향식은 재귀만 가능** - 재귀의 존재 이유
- 하향식 3단계: **이미 구현돼 있다고 상상 → 하위 문제 찾기 → 하위 문제 호출 결과에서 시작.** "세부 사항은 하위 문제에 맡기고" 문제를 뒤로 미룬다
- 기저 조건 비법: 빈 문자열/배열 활용, 계단 문제식 "조작된" 기저 조건
- 계단 문제: 경로(n) = 경로(n-1) + 경로(n-2) + 경로(n-3) - 하향식이 아니면 떠올리기 힘든 풀이
- 애너그램 생성은 **O(N!) 계승 시간** - 지금까지 나온 카테고리 중 가장 느리다

## 연습 문제 (해답 예시)

1. **문자열 배열의 총 문자 수** - `charCount(["ab","c","def","ghij"])` = 10. 첫 문자열 길이 + 나머지 배열의 charCount. 기저 조건은 빈 배열 → 0.
2. **짝수만 담은 새 배열 반환** - 첫 원소가 짝수면 `[첫 원소, ...evenOnly(나머지)]`, 홀수면 `evenOnly(나머지)`. 기저 조건은 빈 배열.
3. **삼각수: N번째 값 = N + (N-1번째 값)** -

   ```typescript
   function triangle(n: number): number {
     if (n === 1) {
       return 1;
     }
     return n + triangle(n - 1);
   }
   ```

4. **"x"의 첫 인덱스** - 첫 문자가 "x"면 0, 아니면 `1 + indexOfX(string.slice(1))`. 하위 문제의 인덱스에 1을 더하며 위로 전달한다.
5. **유일 경로(격자판 최단 경로 수)** - 오른쪽/아래로만 이동하므로 어떤 칸에 도달하는 경로 수 = 위 칸까지의 경로 수 + 왼쪽 칸까지의 경로 수:

   ```typescript
   function uniquePaths(rows: number, columns: number): number {
     if (rows === 1 || columns === 1) {
       return 1;  // 한 줄뿐이면 경로도 하나
     }
     return uniquePaths(rows - 1, columns) + uniquePaths(rows, columns - 1);
   }
   ```
