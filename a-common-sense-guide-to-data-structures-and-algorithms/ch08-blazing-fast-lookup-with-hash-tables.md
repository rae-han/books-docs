# Chapter 8: Blazing Fast Lookup with Hash Tables (해시 테이블로 매우 빠른 룩업)

## 핵심 질문

키만 알면 한 단계 만에 값을 찾는 자료 구조는 어떻게 동작하는가? 충돌은 왜 생기고 어떻게 해결하는가? 그리고 쌍(pair)도 아닌 평범한 배열을 해시 테이블에 넣으면 어떤 마법이 일어나는가?

---

## 1. 메뉴 룩업 문제

패스트푸드점 메뉴(음식-가격)를 배열의 배열 `[["french fries", 0.75], …]`로 저장하면 가격 검색에 선형 검색 O(N), 정렬해 두면 이진 검색 O(log N)이 걸린다. 나쁘지 않지만 훨씬 좋아질 수 있다 — **해시 테이블(*hash table - 키-값 쌍을 저장하며 평균 O(1) 룩업을 제공하는 자료 구조. 언어에 따라 해시, 맵, 해시 맵, 딕셔너리, 연관 배열로 불림*)**은 O(1) 룩업을 제공한다.

```typescript
const menu = { "french fries": 0.75, "hamburger": 2.5, "hot dog": 1.5, "soda": 0.6 };
menu["french fries"];  // 0.75 — 한 단계
```

해시 테이블은 쌍으로 이뤄진 값들의 리스트다. 첫 항목을 **키(key)**, 둘째 항목을 **값(value)**이라 부른다.

## 2. 해시 함수로 해싱

어릴 적 비밀 코드(A=1, B=2, …)처럼 **문자를 숫자로 변환하는 과정을 해싱(hashing)**, 그 변환 규칙을 **해시 함수(hash function)**라 부른다. 예제에서는 "곱셈 해시 함수"(각 문자의 숫자를 곱함)를 쓴다: BAD → 2×1×4 = 8.

> **핵심 통찰**: 유효한 해시 함수의 기준은 단 하나 — **같은 입력에 대해 항상 같은 숫자를 반환**해야 한다. 난수나 현재 시간을 쓰는 함수는 무효다. (한편 곱셈 해시에서 DAB도 8이 된다는 점을 기억해 두자 — 곧 문제가 된다.)

## 3. 해시 테이블의 저장과 룩업

해시 테이블도 내부적으로는 주소가 붙은 셀들의 줄이다. `thesaurus["bad"] = "evil"`을 저장하면:

1. 키를 해싱한다: BAD = 8
2. 값 `"evil"`을 **셀 8**에 넣는다

룩업 `thesaurus["bad"]`도 정확히 같은 두 단계다: 키를 해싱(8) → 셀 8에 가서 값을 반환.

> **핵심 통찰**: **키 자체가 값의 위치를 결정한다.** 값을 넣을 때 키를 해싱해 위치를 정했으므로, 찾을 때도 키를 해싱하면 같은 위치가 나온다. 이것이 해시 테이블 룩업이 O(1)인 이유의 전부다.

### 3.1 단방향 룩업

이 O(1) 마법은 **키로 값을 찾을 때만** 성립한다. 값으로 키를 찾으려면 모든 쌍을 뒤져야 하므로 O(N)이다. 또 키는 테이블에 하나만 존재할 수 있지만(기존 키에 다시 저장하면 값을 덮어씀) 같은 값은 여러 개 있을 수 있다. 키는 (언어에 따라) 값 바로 옆에 함께 저장되곤 하는데, 이는 충돌 처리에서 유용하다.

## 4. 충돌 해결

`thesaurus["dab"] = "pat"`을 추가하면? DAB = 4×1×2 = 8 — 셀 8에는 이미 `"evil"`이 있다. **이미 채워진 셀에 데이터를 추가하는 것을 충돌(collision)**이라 부른다.

고전적 해법이 **분리 연결법(*separate chaining - 충돌한 셀에 값 하나 대신 [키, 값] 하위 배열들의 배열 참조를 넣는 방법*)**이다. 셀 8은 `[["bad", "evil"], ["dab", "pat"]]`이 되고, 룩업 시에는 ① 키 해싱(8) ② 셀 8이 배열임을 확인 ③ 하위 배열들의 인덱스 0을 선형 검색해 `"dab"`을 찾고 인덱스 1의 값을 반환한다.

모든 데이터가 한 셀에 몰리면 해시 테이블은 배열과 다를 게 없어진다 — **최악의 경우 룩업은 O(N)**이다. 그래서 충돌이 거의 없도록 설계해 "평균 O(1)"을 지키는 것이 관건이다(대부분 언어가 알아서 처리하지만, 내부를 알아야 O(1)이 어떻게 유지되는지 이해할 수 있다).

## 5. 효율적인 해시 테이블 만들기

해시 테이블의 효율은 세 요인으로 정해진다:

1. 저장하는 **데이터 양**
2. 사용 가능한 **셀 개수**
3. 사용하는 **해시 함수**

해시 함수가 왜 중요한가: 항상 1~9만 반환하는 해시 함수(자릿수 합을 반복)는 셀 10~16을 영원히 놀리고 1~9에만 데이터를 욱여넣는다. **좋은 해시 함수는 사용 가능한 모든 셀에 데이터를 고르게 분산**시킨다.

셀이 많을수록 충돌은 줄지만 메모리가 낭비된다(항목 5개에 셀 1,000개는 낭비). 이 균형이 **부하율(*load factor - 데이터 개수 / 셀 개수의 비율*)**이며, 경험칙으로 **이상적 부하율은 0.7**(원소 7개당 셀 10개)이다. 데이터가 늘면 언어가 알아서 셀을 늘리고 해시 함수를 바꿔 재분산한다.

## 6. 해시 테이블로 데이터 조직

본래 쌍인 데이터에 해시 테이블은 자연스럽다: 메뉴(음식-가격), 유의어 사전(단어-유의어; 파이썬이 해시 테이블을 "딕셔너리"라 부르는 이유), 득표 집계(후보-득표수), 재고(품목-수량), 속성 객체(`{"Name": "Fido", "Breed": "Pug", …}`).

**조건부 로직 간소화**에도 쓰인다 — if/elsif 사슬로 HTTP 상태 코드의 의미를 반환하던 함수는 사실 쌍 데이터를 다루고 있었던 것:

```typescript
const STATUS_CODES: Record<number, string> = {
  200: "OK", 301: "Moved Permanently", 401: "Unauthorized",
  404: "Not Found", 500: "Internal Server Error",
};

function statusCodeMeaning(number: number): string {
  return STATUS_CODES[number];
}
```

## 7. 해시 테이블로 속도 올리기 — "인덱스로 사용하기"

쌍이 아닌 데이터에도 해시 테이블은 속도 도구가 된다. 배열 `[61, 30, 91, 11, 54, 38, 72]`에서 수를 찾으려면 O(N)이지만, 배열을 이렇게 변환하면:

```typescript
const hashTable = { 61: true, 30: true, 91: true, 11: true, 54: true, 38: true, 72: true };
hashTable[72];  // true — 한 단계
```

> **핵심 통찰**: **배열을 해시 테이블로 변환하면 O(N) 검색이 O(1) 검색으로 바뀐다.** 각 항목을 키로 넣고 값은 아무 참같은(truthy) 값이면 된다 — 룩업이 값을 돌려주면 "있다", nil/undefined면 "없다". 책 뒤의 색인처럼 동작하므로 저자는 이를 **"해시 테이블을 인덱스로 사용하기"**라 부른다. 배열을 반복 검색하는 알고리즘의 단골 최적화다.

### 7.1 배열 부분 집합 — O(N×M)에서 O(N)으로

`["b","d","f"]`가 `["a","b","c","d","e","f"]`의 부분 집합인지 판정하기. 중첩 루프 방식은 작은 배열 × 큰 배열 = **O(N×M)**. 해시 테이블 방식:

```typescript
function isSubset(array1: string[], array2: string[]): boolean {
  const [largerArray, smallerArray] =
    array1.length > array2.length ? [array1, array2] : [array2, array1];

  const hashTable: Record<string, boolean> = {};
  // 1) 큰 배열의 모든 항목을 "인덱스"에 저장
  for (const value of largerArray) {
    hashTable[value] = true;
  }
  // 2) 작은 배열의 각 항목이 인덱스에 있는지 O(1)씩 확인
  for (const value of smallerArray) {
    if (!hashTable[value]) {
      return false;
    }
  }
  return true;
}
```

두 배열 합계 항목 수를 N이라 하면 각 항목을 한 번씩만 처리 → **O(N)**. O(N×M) 대비 엄청난 개선이다.

---

## 요약

- 해시 테이블 = **키-값 쌍** 저장소. **키를 해싱한 결과가 곧 값의 저장 위치** → 룩업·삽입 평균 **O(1)**
- 해시 함수의 유일 조건: **같은 입력 → 항상 같은 출력**
- **충돌**(같은 셀에 두 데이터)은 분리 연결법(셀에 하위 배열)으로 해결 — 몰리면 최악 O(N)이므로 분산이 생명
- 효율 3요소: 데이터 양·셀 개수·해시 함수. **부하율 0.7**이 이상적 균형
- O(1)은 **키→값 단방향**이다. 값→키는 O(N)
- 본래 쌍인 데이터(사전·집계·속성)에 자연스럽고, 조건부 로직도 대체 가능
- **인덱스로 사용하기**: 배열 항목을 키로 넣으면 존재 확인이 O(1) — 반복 검색 알고리즘의 표준 최적화 (부분 집합 판정 O(N×M)→O(N))

## 연습 문제 (해답 예시)

1. **두 배열의 교집합을 O(N)으로** — 첫 배열의 값을 전부 해시 테이블에 키로 저장한 뒤, 둘째 배열을 순회하며 키가 있는 값만 결과에 추가한다 (중첩 루프 없이 각 배열을 한 번씩만 순회).
2. **첫 번째 중복 값을 O(N)으로** — 배열을 순회하며 각 값을 해시 테이블에 기록하되, 기록 전에 이미 키로 존재하면 그 값을 즉시 반환한다.
3. **빠진 알파벳 한 글자를 O(N)으로** — 문자열의 각 문자를 해시 테이블에 기록한 뒤, "abcdefghijklmnopqrstuvwxyz"를 순회하며 테이블에 없는 첫 문자를 반환한다.
4. **첫 번째 비중복 문자를 O(N)으로** — 1차 순회로 문자별 등장 횟수를 해시 테이블에 집계하고, 2차 순회(원래 문자열 순서)에서 횟수가 1인 첫 문자를 반환한다.
