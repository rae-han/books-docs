# Chapter 12: Polymorphism (다형성) - 요약

> 상세 노트: [ch12-polymorphism.md](../notes/ch12-polymorphism.md)

**핵심 질문**: 다형성이란 무엇이고, 객체지향 시스템은 런타임에 어떻게 적절한 메서드를 선택하는가?

## 핵심

- **다형성의 분류**: 유니버설 다형성(매개변수 다형성 - 제네릭, 포함 다형성 - 서브타입)과 임시 다형성(오버로딩, 강제 형변환). 그냥 "다형성"이라 하면 포함(서브타입) 다형성을 뜻한다.
- **상속의 진짜 목적**: 코드 재사용이 아니라 다형성을 위한 서브타입 계층 구축이다. 재사용이 목적이라면 상속을 쓰지 마라.
- **상속의 양면**: 데이터 관점 - 자식 인스턴스 안에 부모 인스턴스가 개념적으로 포함된다. 행동 관점 - 부모의 퍼블릭 메서드가 자식의 인터페이스에 합쳐진다(런타임에 class/parent 포인터를 따라 메서드를 탐색하기 때문).
- **업캐스팅 + 동적 바인딩**: 자식 인스턴스를 부모 타입에 할당할 수 있고(업캐스팅), 실행될 메서드는 런타임에 실제 객체 기반으로 결정된다(동적 바인딩). 이 둘이 OCP를 가능하게 하는 메커니즘이다 - 현재뿐 아니라 미래의 자식 클래스와도 협력할 수 있다.
- **동적 메서드 탐색**: self 참조가 가리키는 객체의 클래스에서 시작해 상속 계층을 거슬러 올라간다(자동적인 메시지 위임 + 동적인 문맥). 오버라이딩은 부모 메서드를 감추고, 오버로딩은 공존한다.
- **self 전송의 함정**: 부모 클래스 메서드(stats) 안에서 `this.getEvaluationMethod()`를 호출하면 탐색이 부모가 아니라 self가 가리키는 자식 클래스에서 다시 시작된다. 강의 평가 예제(Lecture/GradeLecture)의 핵심이며, 깊은 계층 + 오버라이딩과 만나면 이해하기 극단적으로 어려운 코드가 된다.
- **super는 "부모 호출"이 아니다**: super 전송의 의미는 "이 클래스의 부모부터 탐색을 시작하라"다. 그래서 부모에 없는 메서드도 조상 어딘가에 있으면 실행된다. self 탐색 시작점은 런타임에(동적), super는 컴파일타임에(정적) 결정된다.
- **상속 = 자동화된 위임**: 위임은 self 참조를 인자로 넘겨 탐색 문맥을 공유하는 것(포워딩은 self를 안 넘기는 단순 재사용). 상속은 이 self 전달을 자동화한 것이다. JS의 prototype 체인은 클래스 없이 객체 간 위임만으로 다형성을 구현한다 - 클래스는 객체지향의 필수 요소가 아니다.
- **이해할 수 없는 메시지**: 정적 타입 언어는 컴파일 에러, 동적 타입 언어는 method_missing 같은 훅으로 응답할 수 있어 DSL(동적 리셉션)이 가능하지만 디버깅이 어려워진다.

> **핵심 통찰**: 다형성의 실체는 self 참조가 만드는 동적인 탐색 문맥이다. 이 메커니즘을 이해해야 상속이 왜 강력하고 동시에 왜 이해하기 어려운지를 설명할 수 있다.
