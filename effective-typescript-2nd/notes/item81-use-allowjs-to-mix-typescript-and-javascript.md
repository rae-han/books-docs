# Item 81: allowJs로 타입스크립트와 자바스크립트 혼용하기 (Use allowJs to Mix TypeScript and JavaScript)

## 핵심 질문

큰 프로젝트를 한 번에 전환할 수 없다면, 전환 기간 동안 두 언어를 어떻게 공존시키는가?

작은 프로젝트라면 자바스크립트에서 타입스크립트로 단숨에 변환할 수 있다. 하지만 큰 프로젝트에서 이런 "세상을 멈추는" 접근은 통하지 않는다 - **점진적으로** 전환할 수 있어야 하고, 그러려면 타입스크립트와 자바스크립트가 공존할 방법이 필요하다.

그 열쇠가 **`allowJs` 컴파일러 옵션**이다. allowJs가 켜지면 타입스크립트 파일과 자바스크립트 파일이 서로 import할 수 있다. 자바스크립트 파일에 대해 이 모드는 극도로 관대하다 - `@ts-check`(Item 80)를 쓰지 않는 한 문법 에러만 보인다. 가장 사소한 의미에서의 "타입스크립트는 자바스크립트의 슈퍼셋"이다.

에러를 잡아 줄 가능성은 낮지만, allowJs는 **코드 변경을 시작하기 전에 타입스크립트를 빌드 체인에 도입할 기회**를 준다. 좋은 생각이다 - 모듈을 하나씩 타입스크립트로 변환하는 동안(Item 82) 테스트를 계속 돌릴 수 있어야 하기 때문이다.

## 1. 빌드 도구 통합

**번들러**에 타입스크립트 통합이나 플러그인이 있으면 그것이 보통 가장 쉬운 길이다. webpack이라면 ts-loader를 설치하고 설정한다.

```
$ npm install --save-dev ts-loader
```

```javascript
// webpack.config.js
module.exports = {
  module: {
    rules: [
      {
        test: /\.tsx?$/,
        use: 'ts-loader',
        exclude: /node_modules/,
      },
    ],
  },
  // ...
};
```

**유닛 테스트 도구**에도 대부분 이런 옵션이 있다. jest라면 ts-jest를 설치하고 jest.config.js에서 타입스크립트 소스를 통과시킨다.

```javascript
module.exports = {
  transform: {
    '^.+\\.tsx?$': 'ts-jest'
  },
};
```

**Node.js로 실행**한다면 가장 쉬운 것은 ts-node다 - node 명령의 대체품으로 쓰거나 node에 등록해 타입스크립트를 이해하게 한다.

```
$ node -r ts-node/register main.ts
```

## 2. 커스텀 빌드 체인이라면 - outDir 폴백

빌드 체인이 커스텀이라면 일이 더 커진다. 하지만 언제나 좋은 폴백이 있다 - **`outDir` 옵션**을 지정하면 타입스크립트가 소스 트리에 평행한 디렉터리에 순수 자바스크립트 소스를 생성한다. 보통 기존 빌드 체인을 그 위에 돌릴 수 있다. 타입스크립트의 자바스크립트 출력이 원래 소스와 최대한 비슷해지도록(`target`·`module` 옵션 등) 조정이 필요할 수 있다.

> **핵심 통찰**: 타입스크립트를 빌드와 테스트 과정에 넣는 것이 가장 즐거운 작업은 아니겠지만, **자신 있게 코드 마이그레이션을 시작하게 해 주는 필수 작업**이다.

## 기억해야 할 것들

- 프로젝트를 전환하는 동안 자바스크립트와 타입스크립트의 혼용을 지원하려면 `allowJs` 컴파일러 옵션을 사용하라.
- 대규모 마이그레이션을 시작하기 전에 테스트와 빌드 체인이 타입스크립트와 함께 동작하게 만들어라.
