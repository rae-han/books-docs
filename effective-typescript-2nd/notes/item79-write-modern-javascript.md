# Item 79: 모던 자바스크립트 작성하기 (Write Modern JavaScript)

## 핵심 질문

타입스크립트 마이그레이션의 첫걸음이 왜 "자바스크립트 현대화"인가? 어떤 기능부터 채택해야 하는가?

타입스크립트는 타입 안전성 검사에 더해 코드를 어떤 버전의 자바스크립트로든 — 2009년산 ES5까지 — 컴파일한다. 최신 자바스크립트의 슈퍼셋이므로 tsc를 "트랜스파일러"로 쓸 수 있다는 뜻이다. 관점을 바꾸면, **기존 자바스크립트 코드베이스를 타입스크립트로 전환하기로 했다면 최신 자바스크립트 기능을 전부 채택하는 데 아무런 손해가 없다.** 오히려 이득이 크다 — 타입스크립트는 모던 자바스크립트와 함께 동작하도록 설계됐으므로 JS 현대화는 타입스크립트 채택의 훌륭한 첫걸음이다. 그리고 슈퍼셋이므로, 더 모던하고 관용적인 자바스크립트를 배우는 것은 곧 더 나은 타입스크립트를 배우는 것이다.

여기서 "모던"은 ES2015(일명 ES6) 이후 도입된 모든 것이다. 낯선 주제가 있다면 꼭 찾아보라 — async/await 같은 새 언어 기능을 배울 때 타입스크립트가 엄청나게 도움이 된다. 거의 확실히 나보다 그 기능을 잘 이해하고 있고 올바른 사용으로 이끌어 준다.

## 1. 가장 중요한 둘 — ES 모듈과 클래스

**ECMAScript 모듈**: ES2015 이전에는 코드를 모듈로 나누는 표준이 없었다 — 여러 `<script>` 태그, 수동 연결, Makefile, Node식 require, AMD식 define, 타입스크립트 자체 모듈 시스템(Item 72)까지. 지금은 표준이 하나다: `import`와 `export`. 코드베이스가 아직 단일 파일이거나 연결·비표준 모듈 시스템을 쓴다면 ES 모듈로 옮길 때다(webpack이나 ts-node 설정이 필요할 수 있다). 타입스크립트는 ES 모듈과 가장 잘 동작하며, 채택하면 **모듈 단위 마이그레이션**(Item 82)이 가능해진다.

```javascript
// CommonJS
// a.js
const b = require('./b');
console.log(b.name);
// b.js
const name = 'Module B';
module.exports = {name};
```

```typescript
// ECMAScript 모듈
// a.ts
import * as b from './b';
console.log(b.name);
// b.ts
export const name = 'Module B';
```

생성되는 자바스크립트까지 ES 모듈로 바꿀 필요는 없다 — tsconfig의 `module: "commonjs"`면 두 번째 코드가 첫 번째로 컴파일된다.

**프로토타입 대신 클래스**: 자바스크립트의 유연한 프로토타입 기반 객체 모델을 JS 개발자들은 대체로 무시하고 더 경직된 클래스 모델을 선호해 왔고, ES2015의 `class` 키워드로 공식화됐다. 프로토타입을 직접 쓰는 코드는 클래스로 바꿔라.

```javascript
// 프로토타입 — 타입스크립트가 힘들어한다
function Person(first, last) {
  this.first = first;
  this.last = last;
}
Person.prototype.getName = function() {
  return this.first + ' ' + this.last;
}

// 클래스 — 최소한의 구문으로 이해한다
class Person {
  constructor(first, last) {
    this.first = first;
    this.last = last;
  }
  getName() {
    return this.first + ' ' + this.last;
  }
}
```

구식 클래스 코드에는 타입스크립트 언어 서비스가 "Convert function to an ES2015 class" 빠른 수정을 제공한다.

## 2. 그 밖의 기능들

1. **var 대신 let/const**: var에는 기묘한 스코프 규칙이 있다. 피하고 걱정하지 않는 편이 낫다!
2. **C 스타일 for(;;) 대신 for-of 또는 map 등 배열 메서드**: 3부분 for 루프는 불필요한 인덱스 변수를 만들고 실수하기 쉽고 이터레이터에 잘 적응하지 못한다(객체 순회는 Item 60).
3. **콜백·날 프로미스 대신 async/await**: Item 27에서 상세히.
4. **함수 표현식보다 화살표 함수**: 더 간결하고 둘러싼 문맥의 this를 보존한다(this 바인딩은 Item 69).
5. **기본 매개변수 값**: 구현부에서 기본값을 채우는 대신 선언에 직접(`function foo(param=123) {}`). 타입스크립트에서는 기본값에서 매개변수 타입이 추론되는 이점까지 있다.
6. **간결한 객체 리터럴과 구조 분해**: `{x: x}` 대신 `{x}` — 일관된 네이밍을 장려한다. 역으로 `[x, y] = pair`로 풀 수 있고 튜플 타입과 특히 잘 맞는다.
7. **연관 배열에는 객체 대신 Map과 Set**: 객체에서 `"constructor"`나 `"prototype"` 문자열을 읽어 본 적 있다면 이유를 알 것이다. ES2015 컨테이너는 객체와 연관 배열의 혼동에서 오는 많은 문제를 피한다.
8. **옵셔널 체이닝(?.)**: `x && x.y` 대신 `x?.y`. undefined일 수 있는 함수의 조건부 호출은 `fn?.()`. 다만 null 값 자체를 피하는 것이 더 낫다(Item 33·37).
9. **|| 대신 널 병합(??)으로 기본값 채우기**: x가 0이면 `x || 10`은 10이지만 `x ?? 10`은 0이다. truthy와 nullish의 혼동은 버그의 단골 원천이다 — 보통 원하는 것은 null 체크이고 ??가 그것을 해 준다.
10. **"use strict"는 신경 쓰지 마라**: 타입스크립트가 strict 모드보다 엄격하며, 모듈 모드에서는 출력 JS에 "use strict"를 알아서 넣어 준다. 소스에 쓰는 것은 아무 효과가 없다.

> **참고**: TC39는 매우 활발하고 기능이 해마다 추가된다. 타입스크립트 팀은 표준화 stage 3(4단계 중)에 도달한 기능은 구현하기로 약속하고 있어 잉크가 마르길 기다릴 필요도 없다. 최신은 TC39 GitHub 저장소에서 — 집필 시점 기준 Pipeline, Records, Tuples 제안이 특히 타입스크립트에 큰 영향을 줄 잠재력이 있다.

## 기억해야 할 것들

- 타입스크립트는 런타임 환경이 무엇이든 모던 자바스크립트를 쓰게 해 준다. 활용하라 — 코드베이스가 좋아질 뿐 아니라 타입스크립트가 코드를 이해하는 데도 도움이 된다.
- 타입스크립트 마이그레이션이 쉬워지도록 ES 모듈(import/export)과 클래스를 채택하라.
- 클래스·구조 분해·async/await 같은 언어 기능을 배우는 데 타입스크립트를 활용하라.
- 최신 언어 기능은 TC39 GitHub 저장소와 타입스크립트 릴리스 노트에서 확인하라.
