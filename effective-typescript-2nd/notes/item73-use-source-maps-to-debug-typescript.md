# Item 73: 소스맵으로 타입스크립트 디버깅하기 (Use Source Maps to Debug TypeScript)

## 핵심 질문

디버거에 뜨는 것은 생성된 자바스크립트인데, 원본 타입스크립트로 디버깅하려면 어떻게 하는가?

타입스크립트 코드를 실행할 때 실제로 실행되는 것은 컴파일러가 생성한 자바스크립트다. 어떤 소스 대 소스 컴파일러든(압축기·컴파일러·전처리기) 마찬가지다. 이 과정이 대체로 투명해서 자바스크립트를 들여다볼 일 없이 타입스크립트 소스가 실행되는 척할 수 있길 바라지만 - **디버깅해야 하는 순간** 이 환상이 깨진다. 디버거는 실행 중인 코드에서 동작하고 그 코드가 거친 번역 과정을 모른다.

자바스크립트가 워낙 인기 있는 타깃 언어라 브라우저 벤더들이 협력해 이 문제를 풀었다 - 소스맵(*source map - 생성된 파일의 위치·심벌을 원본 소스의 대응 위치·심벌로 되돌려 매핑하는 파일*)이다. 대부분의 브라우저와 많은 IDE가 지원한다. 타입스크립트 디버깅에 안 쓰고 있다면 손해다!

## 1. 왜 필요한가 - 생성된 코드는 원본과 딴판이 된다

버튼 클릭 카운터 같은 단순한 코드는 생성된 자바스크립트(ES5 타깃)도 원본과 닮아서 디버깅이 어렵지 않다. 하지만 numbersapi.com에서 숫자 상식을 가져오도록 `async`/`await`를 추가하면(빠르게 여러 번 누르면 경쟁 조건도 발견할 것이다!) 이야기가 달라진다 - 구형 브라우저에서 async·await를 지원하기 위해 **타입스크립트가 이벤트 핸들러를 상태 기계로 다시 쓰기 때문**이다. 동작은 같지만 코드는 더 이상 원본을 닮지 않는다.

여기서 소스맵이 돕는다. tsconfig.json에 설정한다.

```json
{
  "compilerOptions": {
    "sourceMap": true
  }
}
```

이제 tsc가 .ts 파일마다 출력 두 개를 낸다 - `.js` 파일과 `.js.map` 파일(후자가 소스맵). 이 파일이 있으면 브라우저 디버거에 **index.ts가 새로 나타난다.** 원하는 대로 중단점을 걸고 변수를 들여다볼 수 있다. 파일 목록에서 index.ts가 이탤릭으로 보이는 것은 웹 페이지가 포함한 "진짜" 파일이 아니라 소스맵을 통해 들어왔다는 표시다. 설정에 따라 index.js.map은 index.ts의 참조를 담거나(브라우저가 네트워크로 로드) 인라인 복사본을 담는다(요청 불필요).

## 2. 주의사항

- **번들러·압축기를 쓴다면** 그것들이 자체 소스맵을 생성할 수 있다. 최고의 디버깅 경험을 위해서는 생성된 자바스크립트가 아니라 **원본 타입스크립트 소스까지 끝까지 매핑**되어야 한다. 번들러가 타입스크립트를 내장 지원하면 그냥 되지만, 아니라면 소스맵 입력을 읽게 하는 플래그를 찾아야 할 수 있다.
- **프로덕션에서 소스맵을 서빙하는지 인지하라.** JS 파일이 소스맵 참조만 담고 있다면 디버거를 열 때만 로드되므로 최종 사용자 성능에 영향이 없다(인라인 소스맵은 항상 다운로드되므로 프로덕션에서 피할 것). 소스맵이 **원본 소스 코드의 복사본**을 담고 있다면 공개할 의도가 없던 내용이 나갈 수 있다 - 비꼬는 주석이나 내부 버그 트래커 URL을 온 세상이 봐야 할까?

## 3. Node.js 디버깅

Node.js 프로그램도 소스맵으로 디버깅할 수 있다 - 보통 편집기를 통하거나 브라우저 디버거를 Node 프로세스에 연결한다.

```typescript
// bedtime.ts
async function sleep(ms: number) {
  return new Promise<void>(resolve => setTimeout(resolve, ms));
}
async function main() {
  console.log('Good night!');
  await sleep(1000);
  console.log('Morning already!?');
}
main();
```

(`Promise<void>`의 void는 함수의 void 반환처럼 sleep이 쓸모 있는 값으로 해소되지 않음을 나타낸다.) sourceMap을 켜고 컴파일한 뒤 `--inspect-brk` 플래그로 실행한다.

```
$ tsc bedtime.ts
$ node --inspect-brk bedtime.js
Debugger listening on ws://127.0.0.1:9229/...
```

크롬에서 `chrome://inspect`로 가면 "Inspect"할 수 있는 원격 타깃이 보인다. `--inspect-brk`는 원격 디버깅 프로토콜 웹소켓을 여는 것에 더해 **코드 실행을 맨 처음에 멈춰 준다** - 타입스크립트 뷰로 전환해 원본 소스에 중단점을 설정하기에 편리하다. 자바스크립트의 `debugger` 문도 원하는 지점에 정확히 중단점을 거는 편리한 방법이다.

프로젝트에서 `.d.ts` 파일을 생성한다면(declaration 옵션) `declarationMap` 설정으로 **타입 선언을 원본 소스로 매핑하는 `.d.ts.map`** 도 생성할 수 있다 - 특히 프로젝트 레퍼런스(Item 78)를 쓸 때 "정의로 이동" 같은 언어 서비스가 좋아진다.

> **핵심 통찰**: 타입 체커가 실행 전에 많은 에러를 잡아 주지만 좋은 디버거의 대체물은 아니다. 소스맵으로 훌륭한 타입스크립트 디버깅 경험을 얻어라.

## 기억해야 할 것들

- 생성된 자바스크립트를 디버깅하지 마라. 소스맵으로 런타임에 타입스크립트 코드를 디버깅하라.
- 소스맵이 실제로 실행하는 코드까지 끝까지 매핑되는지 확인하라.
- 타입스크립트로 작성된 Node.js 코드를 디버깅하는 법을 알아 두라.
- 설정에 따라 소스맵에 원본 코드의 인라인 복사본이 담길 수 있다. 무엇을 하는지 알지 못한다면 공개하지 마라!
