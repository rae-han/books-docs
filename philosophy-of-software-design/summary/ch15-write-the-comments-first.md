# Chapter 15: Write The Comments First (주석을 먼저 작성하라) - 요약

> 상세 노트: [ch15-write-the-comments-first.md](../notes/ch15-write-the-comments-first.md)

**핵심 질문**: 주석을 코드보다 먼저 작성하면 어떤 이점이 있는가?

## 핵심

- **늦은 주석은 나쁜 주석**: 코드를 다 쓰고 나면 설계 의도를 잊었고, "빨리 끝내자"는 심리로 대충 쓰게 되며, 주석이 귀찮은 의무가 된다.
- **순서**: 클래스 수준 주석(추상화 정의) 다음에 주요 공개 메서드의 인터페이스 주석, 주요 인스턴스 변수 주석, 마지막에 코드(구현 주석과 함께). 구현이 없는 상태에서 추상화부터 언어로 고정한다.
- **주석은 설계의 리트머스 시험지**: 클래스 주석이 길고 복잡하면 책임 과다, 메서드 주석에 예외 조건이 많으면 인터페이스 복잡, 동작을 설명하기 어려우면 추상화 불량, 관련 없는 것들을 함께 설명해야 하면 관심사 미분리의 신호다.
- **피드백 루프**: 주석 작성, 설계 평가, 설계 개선, 주석 수정을 거친 뒤 코드를 쓴다. 코드 작성 전에 문제를 발견하므로 수정 비용이 주석 몇 줄에 그친다. 코드부터 쓰면 설계 변경 비용이 코드 전체로 커진다.
- **심리적 전환**: 코드 뒤에 쓰는 주석은 지루한 사후 작업이지만, 먼저 쓰는 주석은 "이 모듈을 어떻게 만들까"라는 창의적 설계 과정의 일부가 된다. 태도 자체가 바뀐다.

> **핵심 통찰**: 주석을 쓰기 어렵다는 것은 설계가 잘못되었다는 신호다. 주석 먼저 쓰기는 문서화 기법이 아니라 가장 싼 설계 검증 도구다.
