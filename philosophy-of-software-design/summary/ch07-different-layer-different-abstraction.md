# Chapter 7: Different Layer, Different Abstraction (계층이 다르면 추상화도 달라야 한다) - 요약

> 상세 노트: [ch07-different-layer-different-abstraction.md](../notes/ch07-different-layer-different-abstraction.md)

**핵심 질문**: 인접한 계층이 유사한 추상화를 가지고 있다면 어떤 설계 문제를 나타내는가?

## 핵심

- **원칙**: 잘 설계된 시스템에서 각 계층은 서로 다른 수준의 추상화를 제공한다(네트워크 스택처럼). 인접 계층의 추상화가 비슷하면 계층 분리가 잘못됐다는 신호다.
- **통과 메서드(pass-through method)**: 아무 가치도 더하지 않고 인자를 그대로 하위 메서드에 전달하는 메서드. 인터페이스만 있고 기능이 없는 전형적 얕은 모듈이며, 책임 분배가 잘못됐다는 표시다.
- **통과 메서드 해법 세 가지**: 두 클래스의 추상화가 같으면 합치기, 상위 클래스에 고유한 책임(undo 기록, 리스너 알림 등)을 부여해 재분배하기, 호출자가 하위 객체를 직접 쓰게 하기.
- **인터페이스 중복이 허용되는 경우**: 디스패처(라우팅이라는 고유 역할 수행)와 다형성(같은 시그니처, 다른 구현)은 통과 메서드가 아니다.
- **데코레이터 주의**: 감싸면서 같은 인터페이스를 노출하고 기능을 약간 더하는 패턴은 통과 메서드의 온상이다(Java I/O의 BufferedInputStream). 만들기 전에 기존 클래스에 기능 내장, 기존 데코레이터에 합치기, 독립 클래스화를 먼저 고려한다. 데코레이터가 많다는 건 기본 클래스가 충분히 깊지 않다는 신호다.
- **통과 변수(pass-through variable)**: 중간 메서드들이 쓰지도 않으면서 하위로 전달하려고 들고 있는 변수. 시그니처를 오염시키고 변수 하나 추가에 체인 전체 수정을 유발한다. 공유 컨텍스트 객체로 해결한다(전역은 모호성 유발, 신중히).

## Red Flags

- 🚩 **Pass-Through Method**: 인자를 그대로 전달만 하고 고유 기능이 없는 메서드
- 🚩 **Adjacent Layers with Similar Abstractions**: 인접 계층의 인터페이스가 유사함
- 🚩 **Decorator Proliferation**: 데코레이터 남발은 기본 클래스가 얕다는 신호

> **핵심 통찰**: 계층은 "무엇을 감싸는가"가 아니라 "어떤 새로운 추상화를 제공하는가"로 존재를 정당화해야 한다. 새 추상화가 없는 계층은 복잡성만 더한다.
