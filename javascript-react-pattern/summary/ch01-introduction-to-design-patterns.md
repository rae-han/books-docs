# Chapter 01: Introduction to Design Patterns (디자인 패턴 소개) - 요약

> 상세 노트: [ch01-introduction-to-design-patterns.md](../notes/ch01-introduction-to-design-patterns.md)

**핵심 질문**: 디자인 패턴이란 무엇이며, 왜 현대 자바스크립트 개발에서 여전히 중요한가?

## 핵심

- **기원은 건축학**: 크리스토퍼 알렉산더가 건물/도시 설계의 반복 문제 해결 경험을 패턴 언어로 문서화했고(1977), 이것이 소프트웨어로 전파되어 1995년 GoF(감마, 헬름, 존슨, 블리시드)의 23가지 객체 지향 디자인 패턴으로 체계화됐다.
- **패턴이란**: 반복되는 설계 문제에 적용할 수 있는 재사용 가능한 템플릿. 세 가지 핵심 특성 - 검증됨(앞선 개발자들의 경험의 산물), 재사용 가능(요구에 맞춰 적용), 알아보기 쉬움(정해진 구조와 공통 어휘).
- **부가 이점**: 코드 구조가 잘못될 염려를 덜어 큰 문제를 방지하고, 일반화된 함수로 코드 양을 줄이고(DRY), 팀/커뮤니티와 공통 어휘로 소통하게 하며, 패턴 자체가 커뮤니티에서 개선되는 선순환을 만든다.
- **만능이 아니다**(오스마니): 패턴은 체계화된 방법을 제시할 뿐 설계의 모든 문제를 풀어주지 않는다. 좋은 패턴을 고르려면 여전히 좋은 설계자가 필요하다. 프레임워크가 이미 잘 설계돼 있어 패턴이 불필요할 수도, 반대로 특정 패턴을 강제할 수도 있다.
- **일상 속 패턴 - 공급자 패턴**: 컴포넌트 트리 깊숙이 prop을 계속 내려보내는 프롭 드릴링 문제를, 리액트 Context Provider + useContext로 여러 컴포넌트에 한 번에 데이터를 공급해 해결한다. 이미 쓰고 있는 코드에 이름을 붙이는 것이 패턴 학습의 실체다.
- **현대적 맥락**: 모듈, 클래스, 화살표 함수 등 언어의 발전과 React 19/Next.js 15 생태계 변화(노트에 2026 업데이트 반영) 속에서도 패턴의 원칙은 언어/프레임워크 독립적으로 유효하다.

> **핵심 통찰**: 패턴의 가치는 외워서 적용하는 데 있지 않고, 무의식적으로 작성하던 코드 구조에 이름을 붙이고 그 특징을 명확히 이해하는 데 있다. "이 패턴을 썼습니다" 한마디가 코드의 의도를 전달한다.
